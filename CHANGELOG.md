# Changelog

All notable changes to Dom are recorded here, newest first. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions are git tags
named `vX.Y.Z`.

## [Unreleased]

## [0.8.6.1] - 2026-11-28

- **Triage confidence, bot-to-bot limits, and ending conversations.** `[dispatch]` now exposes live-configurable `triage_confidence` (default `0.35`, down from the hardcoded `0.70` so Jev can act on stay-quiet and react-only verdicts), `bot_depth_limit` (default `3`, down from `6`), and `bot_reply_interval_seconds` (default `10`). All three are editable in **Settings → What Dom may do → Messaging → Triage & bot loops** and apply immediately without restarting. The chat prompt (`FRAME`) now explicitly tells Dom how to stay silent (`no_response: true`) or react-only when a conversation is wrapping up or over so he stops feeding goodbye loops.
- **See and hear media from other bots.** Added `dispatch.bot_media` (default `false`, live switch in **Settings → What Dom may do → Messaging**) so Dom can optionally see and hear photos, stickers, voice notes and videos sent by other bots while still blocking bot-sent documents from landing in the workspace.
- **Local speech-to-text with cloud fallback.** Added `[stt]` (`base_url`, `model`, `language`, `api_key_env`), editable and testable live in **Settings → Models → Local speech-to-text**. When the chat model does not accept audio natively, voice notes, audio files, and video/video-note soundtracks try the local OpenAI-compatible `/audio/transcriptions` server first and fall back automatically to `[models.media]` if it is unreachable or fails.
- **Auto-refreshing model modality probes.** Cached probes for home/OpenAI-compatible chat endpoints now expire after 30 minutes (`Modalities.PROBE_TTL`, bounded in memory as well) and reset when routes change, so enabling vision on a local server is picked up automatically in the background (or immediately via **Probe again** in Settings → Models). Fixed the Models UI badge showing `Unknown` instead of `Text only` after a probe finds no media inputs.

## [0.8.6] - 2026-11-27

- **Talk fits a phone, and sends files.** On a phone the Talk page is exactly the visible screen, like a chat app: the conversation scrolls inside its card, the composer stays at the bottom (on the keyboard while you write, following Safari's address bar and keyboard through the visual viewport), and the page itself no longer scrolls into an empty area below the composer. The cause was the screen-reader text inside the conversation, positioned against the page rather than the scrolled list, so a long conversation stretched the page; the desktop's page lost the same few hundred pixels of empty space. A paperclip button beside the photo button sends any file as a document, up to 20 MB as in Telegram: it is mirrored to your DM as a document and lands in `workspace/inbox/` through the same code as a document sent there, so Dom sees its name, type and path and reads it with `files`.
- **Dom keeps his word, and talks less.** A reply that says Dom is about to do something ("i'll add it", "let me check", "on it") when no tool was called is put back to the model once with the tools still on offer, to call the tool or reword; a second answer is sent as it stands, and the turn log shows `Action promise put back`. Openers, noticings, tool-free turns and the bot exit are left alone. Replies are also shorter: one bubble is the normal reply, the cap is 4 bubbles (it was 6, extra ones still join the last), and the prompt asks Dom to match the energy of the moment instead of always sending several enthusiastic bubbles.
- **Openers can send studio media.** An opener's note already offered a voice note, video note or photo, but a media-only opener was dropped and a text-plus-media one never sent its media. An opener's media now goes through the same screen as a reply's (the per-chat switches, private-text and leak checks) and the same studio queue (the rolling limits, spontaneity scaling, event-day ceiling and spend caps), and counts as the opener and as Dom's last message, and as a goal check-in, only once it is sent; media the studio then refuses leaves nothing booked. In a group or a friend's DM the media is checked again up to the send (the chat can still be written to, Dom is still around, nobody wrote meanwhile, openers are still on), and is dropped if not; in your DM, like a reply's media, it is not.
- **A failed subscription agent no longer fails the model switch.** When the escalation card pins a subscription agent and it is refused, missing, signed out or times out, the task goes to the next configured escalation provider, which then serves the rest of the task (the agent is not tried again, and you are told once), on Switch and on Retry, and Dom sends you a short note that it did, since the card had said it was billed to your subscription. A cloud provider pinned on the card is still never failed over. An agent that cannot be started with its tools off (Codex or Antigravity enabled by hand) or is not switched on is never counted as available, so it is never pinned.
- **The Turn log shows rejected reactions.** A turn whose reaction Telegram refused carries a "Reaction rejected" chip with Telegram's reason in its tooltip and in its details, and the log's header counts the rejected reactions of the last 7 days, with the reasons on hover (hidden when there are none).
- **A desktop for groups and friends.** When someone in a group or a friend's DM asks for something that needs the web, Dom may propose a small desktop task (`request_guest_desktop`). The owner gets a card with the chat, who asked, the request (fenced as untrusted) and the limits, with Allow once and Reject only (`guest_desktop` is always asked, never Allow always; Never turns it off), and the asker hears "let me check", then a kind vague no on Reject or expiry. An allowed task runs one at a time in a `guest` container with no browser profile mount (so no saved logins, and nothing survives the task), no workspace and the owner's sessions out of reach, started fresh for every task and removed when it ends (a remote host never runs one, because Dom cannot reset its browser, and `guest = true` on a host is refused at load); on a single-container host it queues behind the owner's task and an idle owner container is stopped to make room. It gets the read-only browser of self-directed work (public pages, links and one search box, no shell, files, uploads, handoff or logins, each refused in code), 15 steps and 5 minutes, and `[desktop.guest]` limits of $0.25 a task and $1.00 a day per chat, recorded as `desktop` spend for that chat under the spend caps; the final answer and the failure message run under the same caps (at a cap the chat gets a fixed line and no model call). Every page action is checked against the owner's site rules, so a link or redirect to a Never site ends in a refusal and a closed page (Ask counts as Never for a guest). Only a final answer Dom writes from the result goes back to the chat (no addresses, screenshots or page text, and checked against private notes); the brief is refused in code if it repeats a private note or credential. The owner sees the full task on Work, marked as a guest task with its chat.
- **Friends can book time with you, inside windows you set.** Tell Dom in your DM when you are willing to meet ("weekday evenings 7 to 10, Saturday afternoons"), or set the windows in Settings → Services → Google, with the least notice, how far ahead and whether a friend is invited to the event. When a friend asks to meet, in their DM or in a group, Dom offers up to three times inside a window that are free on your calendar and his own, and shares nothing else: his free/busy read asks Google for times only. When they pick one you get a card (Allow once, Reject) with who, where, when and what about; only then does he add it to a calendar of his called Dom - Bookings, with the friend as a guest only if you allowed it and their email is known, and tell them. Every decline (a rejection, an expiry, a switch turned off, a restart, a time taken or no longer in your windows or notice, a failed write) tells them the same kind line, never why, and you get a short notice with the reason. Dom checks the time again when you approve, two friends are never offered the same time, a double tap books once, no lock is held while Google is called, and daylight-saving changes neither offer a time that does not exist nor shorten a meeting. With no windows he books nothing; "Confirm a booking" in Access can be set to Allow to skip the card. Offers are kept in the database (migration 0039) and last four hours. A booking caught mid-write by a restart is settled by asking Google whether the event was made, a friend's turn is never told why nothing was offered, and the end time shown stays right across a clock change.
- **Subscription agents, a pilot.** Codex (`codex-acp`), Claude (`claude-agent-acp`) and Antigravity (`agy acp`) on your own subscriptions can serve as the escalation and drafting model, in your DM only, each behind its own switch in Settings → Models (`[acp.<name>] enabled`), off by default and warned as not zero data retention and possibly against the provider's terms. A hand-written ACP client starts the agent fresh for each call, only with its own tools switched off and every permission request refused, in an environment of `PATH`, `HOME` and the locale alone, and kills its whole process group on timeout, cancel or exit; only an owner-DM turn's escalation and drafting reaches it, never background work under the owner's chat id, and a malformed tool call from it is kept as text. Only Claude can be switched on in v0.8.6, and it is started without your own MCP servers, settings files and claude.ai connectors as well as its built-in tools (checked live: with its tools off alone it still offered them). Antigravity cannot be switched on yet, since `agy acp` has no way to turn its tools off, and Codex cannot either, since it loads your own MCP servers and plugins and its session did not open under them; Dom keeps its own tool loop and parses the reply as usual. An agent can run on a Mac over SSH. Calls are usage of kind `subscription` at cost 0, so spend caps are not fooled, and the Turn log and Trace show the agent, its time and any failure. See [Subscription agents](docs/acp-agents.md).
- **A shared workspace.** `<home>/workspace` (owner-only) is one folder for Dom, the owner's desktop and the dashboard: a local desktop container mounts it at `/workspace`, Dom reads and writes it with the owner-DM `files` tool (list, read text, Markdown, CSV, JSON and PDF text, write, move, delete; every path walked without following links, sizes capped, nothing outside it reachable), and a document sent in the owner DM, with any caption, now lands in `workspace/inbox/` (up to 20 MB, saved in the background) with its name and type in the `<media>` tag and its path told to Dom. `/desktop` documents still stage for the task and also land there. PDF text needs `pypdf`, a new dependency. Work → Files browses the workspace and Dom's readable files (memory, media, briefs, skills) with text and image preview, upload, download and a confirmed delete. `[workspace] share_with_chats` (off; Settings → What Dom may do) lets groups and friends read `workspace/shared/` only, never write, and sent documents land in `shared/inbox/<chat id>/` for that chat alone. See [The shared workspace](docs/desktop.md#the-shared-workspace). Hardened after review: a file with several names (a hard link the desktop made) is never read, served or archived; PDFs are parsed in a killable process with memory, CPU and time limits; `dom backup` walks the workspace by directory descriptors and archives only single-name regular files up to the cap; the 500 MB cap is enforced by watching (a running desktop task stops, new work is refused, the owner gets one notice with a link to Files, and `dom doctor` shows the size); the desktop starts without the workspace, and says why, when its user cannot write to the folder; and a document that lands after the reply gets a normal turn (the original request, the history and the file open to his tools), once.
- **The workspace cap and backup, reworked after review.** The 500 MB cap is documented as soft, with one write able to overshoot before the next check, and is measured fresh at task end, task start and on the Files page; `dom backup` leaves out only the exact `.incoming-` files the workspace stages, not every `.incoming-` name, and when the cap bites it keeps the newest files first and logs what it skipped.
- **A bot change no longer hides or drops new messages.** A new bot token restarts Telegram's message numbers in every private chat and basic group (supergroups keep theirs). That left old read markers and memory cursors above every new message (Dom saw nothing unread and the memory pass skipped the chat), and a new message numbered like an old one was taken for it and lost. Dom now stores the bot's id. Only a real change acts: when the id differs, each chat moves the old bot's rows to negative ids (in order, with their reply links and notes) the moment the new bot first writes there; they stay in the history but are never unread, memorised or replied to, and old cards and requests in your DM are expired. An instance that switched before this release is repaired once from its history, only when the evidence is clear (a new run of at least three messages, created after the old ones, starting under a tenth of the old newest id and never passing it); once one chat proves it, every other private chat and basic group whose messages all predate the new bot is set aside when the new bot first writes there, and a chat that only looked switched is repaired too. A late edit or an odd message with a lower id never moves anything. Each repaired chat's read marker goes to Dom's latest reply in the new run (what he answered stays read, so nothing is answered twice) and its memory cursor to 0 so the memory pass catches up; a note lands in your DM history. A normal restart changes nothing, and the first start only stores the id. The importer counts history from the latest run only. A chat that looks switched but has too little evidence yet (under three new messages, or equal times) stays open: it is logged and listed by `dom doctor` at every start and checked again until it is proven or the chat climbs back past the old ids. The old bot's cards and requests in your DM expire the moment the change is seen, not when the new bot first writes, so settling one never edits a message number the new bot reuses.
- **Studio health survives Wi-Fi spikes.** The health check deadline is now 10 s (was 3 s), one failed check keeps the last good health for one more minute (and through a probe still running) and only two in a row mark the studio away (so media stays off paid backups), and a refused connection still marks it away at once. Studio log lines name the request, and one failed check logs at INFO.
- **Watching rejected reactions.** When Telegram refuses a reaction, the log names the emoji, the message and Telegram's reason, the turn gets a `reaction rejected` step and a trace event with the reason, `/api/system/turns` marks the row (`reaction_rejected`) and reports the week's count with the latest reasons.
- **A tidier dashboard.** The Memory file list has a filter, groups with sticky headings and compact rows. Work's tasks read as a short title (the brief's first clause), a status chip and the result's first line, with delete in a row menu. Chats → Your DM shows Talk's bubbles, and the (i) on Dom's names the turn that sent them: model, tokens in, cached and out, cost, time taken and lane (`GET /api/chats/{id}/messages` adds them for your DM: each message is matched to its own turn, and the cost is the usage rows that turn's own calls wrote, now linked by a `usage.turn_id` column, so background passes and other turns never count; older turns show no cost). Access uses Settings' section tabs. The sidebar drops the "Quiet Orbit" subtitle and the Workspace list, which repeated Work's and System's tabs, and keeps Waiting for you at its foot with its count. Phone tab strips open where they were, with no jump or slide. Talk on a phone fills the screen under its header, keeps Trace and Dom right now in the card's own bar, and puts the composer on the keyboard.
- **One conversation about soul and world.** The dashboard's talk with Dom about SOUL.md now covers WORLD.md too (E117): he may propose a line to add, replace or remove in either file, filed as a waiting proposal and changed only when you approve. It never touches a line you pinned or one tagged to a chat, checked when he proposes it and again on approval. An approved edit is your call, so it doesn't use up Dom's weekly world change, and its line is his, not pinned. It opens from SOUL.md, from WORLD.md and from the World page.
- **How readily Dom adds media.** `studio.spontaneity` (Settings → What Dom may do → Media: rarely, sometimes or often; sometimes is today's behaviour) changes the studio turn note's wording and scales every per-chat media limit (halved or doubled) and gap (doubled or halved) in replies and openers alike, always inside the global daily total, the switches and the spend caps, and never past an event day's ceiling when the two meet.
- **Dom watches clips as frame strips.** A video, animation or video note his chat model can't take as video is cut with ffmpeg into images of evenly spaced, time-stamped frames (a frame every 2 to 5 seconds, up to 16 per strip, every frame and sheet size-bounded) plus a transcript of its sound (the media route's audio input, else the chat model's, else none and the note says so), both on arrival in the background. The chat model sees the whole clip: each strip is an image on its turn (up to four, up to 5 minutes 20 seconds, with a note when cut or when frames could not be read), squeezed into the free `media_input_images` slots when there are fewer. The media model describes the strips one at a time only when the chat model takes no images or the turn has no slot left, and the Turn log says so. Clips up to Telegram's 20 MB are taken, one download at a time, with a running job shared rather than repeated. The strips are kept beside the media files, count toward `studio.keep_cap_mb`, and feed Dom's later description. Without ffmpeg, or for a clip that can't be read, the media model describes the whole clip as before.
- **Dom keeps his own calendars.** Google now also asks for `calendar.app.created`, and Dom's calendar writes go only to calendars he made himself, never to your primary calendar. He asks you with a card (Reject, Allow once, never Allow always) before making each new one, keeps their ids encrypted, and code refuses any other target before a card is sent. An event he adds or moves can carry `nudge_minutes`: he reminds you before it through the ordinary reminders in your DM only, and moving or deleting the event moves or cancels the reminder. Settings → Services → Google lists his calendars with colour and upcoming events, and a trash button deletes one at Google after a confirm, with the write switch on or off. Dom's calendar list follows the Google account (a different account sets the earlier one's aside and cancels its nudges), a write runs with its calendar locked and checked, two waiting cards cannot make a sixth calendar, and `primary` or an email can't name one. Connections made before this one keep reading and everything else, and the card says "Reconnect to let Dom keep his own calendars" until Google grants the scope; add it to your consent screen first.
- **Drive writes are never approved half-seen, and range reads are bounded.** The text or cells Dom is about to write now count as material on the approval card, like a recipient: if they do not fit Telegram whole the card shows none of them and sends you to the dashboard, which shows everything. A Sheets range read is cut to 200 rows by 26 columns before Google is asked, and an oversized answer is refused while it arrives instead of being parsed whole.
- **Drive, Docs, Sheets and Contacts.** Two new switches in Settings → Services → Google (off by default, owner DM only, each asked of Google only when you want it: a connection without the permission shows **Reconnect to allow**). Files in Google Drive uses `drive.file` alone, so Dom sees only files he made, in his own folder "Dom", and files you hand him: he lists, searches and reads them (Docs, Sheets by range or CSV, Slides and text files, fenced as untrusted and size-bounded) and, after an approval card showing the file name and the exact text or cells (and what a replace overwrites), creates Docs and Sheets, adds text to a Doc, adds rows to a Sheet and replaces cells, each its own Allow-always kind. Contacts (`contacts.readonly`) looks up a name for an email address or phone number, read only, and `contact_email()` returns one unambiguous address for later use (booking invites a friend only by the email they give in the chat). Send a Drive or Docs link in your DM and Dom answers with a one-tap link to a dashboard page that opens Google's file picker on that file: picking it is what grants Dom access, because a shared link alone grants nothing. It needs `GOOGLE_PICKER_API_KEY` and `GOOGLE_PROJECT_NUMBER` in `.env` (see [Google](docs/google.md)); the page sits behind the dashboard login with its own CSP, and the dashboard lists his folder and the names of the files he may see.
- **Overnight news.** With `[world] news` on (the default), a place or country and a web search route that returns result lists, Dom reads the news for where you are each evening before he sleeps (a missed evening is made up once the news is over 26 hours old, a failed try waits 6 hours): a few searches and one picking call write at most eight dated headlines to `memory/NEWS.md`, replaced each night, and for the next 36 hours every chat's world note carries one or two inside a fenced untrusted element. The model writes no kept text: each line is a result's own title and domain, kept only when the pick matches the title and nothing in it reads as an instruction, and filtered again on reading, with one triage-model (Jev) call each night as a second layer that keeps only the headlines it is confident do not try to steer a bot (no screen, no news); chats other than your DM see the headline alone. The reply path only reads the file; the searches count toward the search limit and the call is attributed as `news` (background spend rules). A failed night leaves the file as it was, and with no search route nothing runs.

## [0.8.5] - 2026-11-27

Dom gets hands, a world of his own and a window into how he thinks. He can browse for you behind per-site approvals, fill saved logins without ever seeing the password, ask you for a secret through a private form, and read your Calendar and Gmail with every change on a card. He has a life sheet with places and routines, a Talk page in the dashboard with a full debug trace of every turn, an owner-DM lane that never waits behind a group, an optional morning plan and evening wrap-up, and video notes whose faces finally move.

- **Assistant mode.** An owner-set switch (`[assistant] enabled`, `/assistant on|off|status`, Settings → What Dom may do) that keeps your day in view in your DM only: a morning plan (calendar, reminders, goals, weather and holiday) and an evening wrap-up, each with its own local time or off, sent once a day even across restarts, late only within three hours, deferred while Dom sleeps, and skipped on an empty day. In your DM he also sees reminders due within a day and goals gone stale, and may check in, never twice about one thing in a day. Plans are background work under the `assistant` usage kind (monthly cap and area limits, not the daily cap); Settings shows when each was last sent or why not. Off, nothing changes, and it never reaches groups or friends' DMs. Booking is not built yet.
- **Titles for chats Dom has never seen.** Notes copied from another instance can name groups this bot has no row for, which the dashboard showed as `Group <id>`. A background pass now asks Telegram for each such group's title, named by a note's file name or a `{chat <id>}` tag (at most three asks a pass, two seconds apart, never on a reply) and keeps it in the chats table, or in a `chat_title:<id>` kv entry when there is no row. A title never replaces one a live message wrote, a rate limit is waited out, and only a sure refusal (not a member, chat not found) keeps the group as `Group <id>`, asked again no sooner than a day later.
- **Dom knows the public holidays.** Set `[world] country` to a two-letter ISO code (for example `SG`) and every turn note carries one line with today's public holiday and the next one within 14 days, from the free, key-less Nager.Date API. It is fetched in the background about once a day and cached, so no reply waits on it, and "today" is the date in your `timezone`; only the country code and the year leave the host. A failed fetch leaves the line out once the cache is a week old. News and local events are not included, since no free key-less source was reliable enough.
- **Media used and left for every chat.** The Chats page has a Media button on each chat, showing what that chat has used and has left of voice notes, video notes, photos and special videos against the limits of its own kind (friend DM or group) and its own deliveries, from the owner-only `GET /api/chats/{id}/media`. The Media limits page now shows used as well as left for your DM.
- **Promised media is nudged, never faked.** When a bubble says "sending you a pic" or "here's a voice note" and the matching `image`, `voice` or `video_note` field is empty, Dom's reply goes back to the model once to set the field or drop the promise (when that media isn't on offer, only to drop it). A fixed phrase list finds the promise, in English with a little Singlish, only when it is made to the reader and never in a question, a negation, a quote, a bubble with a link or a promise to someone else. If the promise still stands after that one nudge, or the nudge fails, it is cut out of the bubbles instead of sent. The turn log records `media promise` steps.
- **Google Calendar and Gmail, behind OAuth and approval cards.** Settings → Services has a Google card: Connect Google runs an authorization-code flow with PKCE and a single-use, ten-minute `state` bound to the browser, keeps the tokens in the encrypted secret store, and Disconnect revokes them at Google. Four switches (Calendar read, Calendar write, Gmail read, Gmail drafts), each off until the owner turns it on, decide which tools Dom is offered, in the owner DM only. Dom lists events and free/busy, keeps a cached today-and-tomorrow block in the owner DM's turn note, searches and reads mail (fenced as untrusted data), and adds, moves or deletes events and saves drafts only after an owner-DM card (Reject, Allow once, Allow always, per kind; the Access page shows each kind's policy). He can never send mail. An expired or revoked token sends one quiet notice and marks Google disconnected. See [Google Calendar and Gmail](docs/google.md).
- **Desktop browser permissions, saved logins, and secure secret requests.** Added an AES-256-GCM encrypted secret store (`DOM_MASTER_KEY` in `.env`, with crash-safe rotation via `dom rotate-key` or the dashboard, reusable by upcoming OAuth integrations), per-action and per-site desktop permissions (`Ask` / `Allow` / `Never` across visiting unfamiliar sites, filling saved logins, downloading, uploading, and background work) with owner-DM approval cards (`Allow once`, `Allow always`, `Reject`), zero-model/untraced VNC keystroke filling for saved logins on verified HTTPS password inputs, the owner-DM-only `request_secret` tool with a one-time `/app/secret` dashboard entry form, and the **System → Access** dashboard page for saved logins, site permissions, and approvals history.
- **Talk to Dom from the dashboard, with a full debug trace.** A new Talk page is the owner DM itself. What you type goes to Telegram as a silent `🖥` mirror and is recorded as your own message (`origin = 'dashboard'`). Dom answers in both places, and the page streams his bubbles as they're sent, with a typing row, photos both ways and a side panel with his presence, the approvals waiting and his desktop task. The Trace switch puts each turn's audit between the messages: arrival and Jev's triage, the exact prompt with its cache fingerprints, every model call's full request and response (reasoning included), tools, the leak scan and look-before-send, each bubble as sent, and the work after the turn (the staying-online check, studio jobs, the memory pass and its ops). JSON shows folded and highlighted, with copy and export buttons. Every chat is traced in full, friends and groups too. Secrets are redacted before storage and traces are written after the turn, off the reply path, to `traces.db` (`[tracer] retention_days = 7`, `max_mb = 256`, oldest first). The Turn log links each turn to its trace. Exports are at `/api/traces/turn/<id>/export` and `/api/traces/export?chat=&from=&to=`.
- **Dom has a world.** `memory/WORLD.md` is his life sheet (home, work, routine by weekday and part of the day, regular spots, projects): the owner edits it and those lines are pinned, and the nightly reflection may change it at most once a week, with a reason, never over a pinned or chat-tagged line. Every turn note's "world now" block, after the chat window and never in the cached prefix, adds the sheet, today's routine slot ("Thursday evening: usually gym"), what the notes say about that slot's places and a variety hint when Dom just said one of his usual options (no more "cai fan" for lunch and dinner), all through the same tag rules, so a group or friend's DM only reads lines it may. A place note can carry a reference photo, added on the new World page (Memory, World): it is kept like kept media without its camera data and goes to a cloud image model that takes references only when Dom names the place by its key on the picture (`image_place`, or `place` on a video note's scene) and the chat may see it, never because the scene's words mention it; the turn note lists the keys a chat may use. The weekly limit is kept in `memory/WORLD.change.json`, claimed before the sheet is written, so a crash or two proposals at once can't change it twice. The World page also shows the sheet, when and why Dom last changed it, and the places.
- **Your DM has a lane of its own.** With `dispatch.fast_lane` (on by default), Dom composes your DM's turns, and the turns your approval cards start, on a token apart from every other chat's, so a long turn in a group or a friend's DM never makes you wait. One chat's turns still run one at a time and in order, and the lanes share the prompt prefix, the spend caps and the usage log. The Turn log shows each turn's lane and how long it waited for its token. Off, every chat shares one token as before.
- **Video notes that move.** A video note's still now always asks for Dom facing the camera with nothing over his face, and the local studio's FlashHead notes crop it to his head and shoulders before animating, so his mouth and eyes visibly move instead of a small figure across the room barely changing. A still with no face, or with more than one, is animated whole.
- **Release-gate fixes.** Untagged lines in a place note stay in your DM: they no longer reach a group's or a friend's world block, and a place known only through them is never offered there for a photo. With Visit unfamiliar sites set to Ask, any page a click, a form, a redirect or a late navigation reaches outside the sites the task was cleared for now asks too, and a rejection closes the page; waiting for a card no longer runs out the task's time. Calendar and Gmail details written into your DM's history are fenced as untrusted text. Each trace has a `window` event with the window's size and whether it was trimmed. The Google OAuth callback skips the dashboard identity check only on a token-only dashboard: with Cloudflare Access configured it needs an Access identity like every request. `dom backup` keeps the owner's place photos (`media/places/`). Assistant plans appear in the Turn log and Trace view, are text only, never go through Jev's prose rescue, run under your DM's turn slot (holding back if you write meanwhile), and a wrap-up that waited past midnight is marked skipped. The Turn log's trace link opens the standalone trace page for every turn, Google approvals are labelled as such on Waiting, and the World editor's counter leaves tags out.

## [0.8.4] - 2026-11-27
