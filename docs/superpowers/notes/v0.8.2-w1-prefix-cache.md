# W1 first-bubble timing and prefix cache

## What Dev recorded

The v0.8.1 cloud baseline for the owner DM was 8.3 s and 11.1 s from message
to first bubble. The two model calls that started those turns took 1.9 s
and 3.0 s. This is the baseline for the post-change Dev comparison.

The home-lab endpoint reported zero cached tokens on all four recorded
first chat calls. The two closest owner-DM turn rows were 33 s apart. Their
system, tool and pre-window user hashes matched, and the prompt log shows
the same first window message. The full user hash changed as the window
grew. The turn note also carries turn-specific context. The second row's
first call had 5,917 input tokens and zero cached tokens. A restarted
attempt in that turn kept the same three prefix hashes and reused 3,264
of 6,019 input tokens.

The engine logs show vLLM running the Qwen3.5 hybrid model with prefix
caching enabled, aligned recurrent-state caching, 816-token blocks and a
4,896-token checkpoint retention interval. The 3,264-token hit is exactly
four blocks. A growing window can diverge before the previous request's
retained state boundary, even if all three Dom hashes match. The engine
also requires the corresponding attention blocks to remain in cache.
Checkpoint placement is consistent with the sample. The turn hashes and
engine logs cannot distinguish a missing checkpoint from an evicted block
for those historical requests.
[vLLM hybrid cache](https://docs.vllm.ai/en/latest/design/hybrid_kv_cache_manager/)
[vLLM cache retention settings](https://docs.vllm.ai/en/latest/configuration/engine_args/#prefix-cache-retention-interval)

## What Dom controls

- The clock, availability, mood and notes-staleness cue already follow the
  window. Stored message timestamps travel with the messages they describe.
  Appending a message extends the window. Edits and trims can still change
  it earlier.
- Sliders, preset overlays and the reason for a self-picked preset now
  follow the window. The active persona still applies immediately.
- Participant notes render in participant ID order. Participants with no
  note contribute no bytes, so an hourly refresh or trim can keep the same
  pre-window prefix when only participant order or empty entries changed.
- The tool list is ordered by scope and plugin name. A real capability or
  plugin change can still change a schema. Edits to SOUL.md, HABITS.md,
  approved skills or refreshed memory and notes can still change the
  corresponding prefix.

The regression test drives two consecutive turns through request assembly
and checks the tools, system message and bytes up to the window. It also
checks that the second turn receives the new preset. The live v0.8.2
first-bubble comparison and cache hit rate are pending Dev testing.
