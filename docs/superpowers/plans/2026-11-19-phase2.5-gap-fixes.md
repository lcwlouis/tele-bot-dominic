# Phase 2.5 — Gap fixes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** close the gaps G1, G4, G5, G7, G10 and G11 from the roadmap before phase 3 builds on them.

**Spec:** `docs/superpowers/plans/2026-11-19-roadmap-phases-3-7.md` ("Gaps found in what is already live") and the design spec §4–§7.

## Global Constraints

- All earlier Global Constraints hold: no real Telegram IDs, handles, chat titles, LAN addresses, domains or names in code, tests or docs; no network in tests.
- Privacy invariant: content from `private/` or the owner's DM never reaches a non-owner prompt, tool result or message.
- The gate is re-checked inside the per-chat turn lock before any model or Jev call.
- One commit per task; the full suite passes before each commit.

## Review Focus

1. **A friend tells Dom something in a DM**, then a group pass or group prompt runs: nothing from the DM appears. *(Task 1.)*
2. **A provider response with no `usage`** (the homelab may omit cost): recorded as zero cost, never a crash. *(Task 2.)*
3. **The spend cap trips mid-conversation:** non-owner chats stop making paid calls; the owner DM keeps working; the owner is told once per day, not once per message. *(Task 2.)*
4. **A backup while Dom is writing:** the SQLite copy is consistent (uses the backup API, not a file copy). *(Task 3.)*
5. **Jev down while the owner DM is offline:** no wake on the urgency rule; the count rule still works. *(Task 4.)*

### Task 2 (G4 + G11): usage, spend cap, model visibility

**Files:** `dom/usage.py` (new), `dom/llm.py`, `dom/jev.py`, `dom/store/migrations/0006_usage.sql`, `dom/store/store.py`, `dom/config.py`, `dom/starter_home/config.toml`, `dom/dispatch.py`, `dom/memory_pass.py`, `dom/media.py`, `dom/telegram/owner.py`, tests.

- **Table `usage`:** `id, at (UTC ISO), kind ('chat'|'triage'|'media'|'memory'), model, endpoint_host, chat_id, input_tokens, output_tokens, cost_usd, fallback (0/1)`.
- **Recording:** `ChatClient.complete` and `JevClient.decide` return usage to a `UsageRecorder` passed at construction (`record(kind, model, host, usage: dict | None, chat_id=None, fallback=False)`). `cost_usd` comes from the response's `usage.cost` when present, else 0. Missing or malformed `usage` records zeros.
  - The `kind` is set by the caller (reply turn, memory pass, media description).
- **`FallbackClient`:** remembers `last_model` and `last_fallback_at`; fallback calls are recorded with `fallback=1`.
- **Spend cap:** config `daily_spend_cap_usd` (default `1.0`; `0` disables). The day is the owner's timezone day.
  - Before any model or Jev call for a **non-owner** chat (turn, triage, media, memory pass), `Usage.over_cap()` is checked. Over the cap: skip the call (treated like "no response"; messages stay unread).
  - The owner DM is never blocked.
  - The first time the cap trips on a given day, the owner gets one DM: "Daily spend cap of $X reached ($Y spent). Friends' chats are paused until midnight. Change `daily_spend_cap_usd` in config.toml." Recorded as an owner event.
- **`/status` footer** gains: `Today: N calls · $X.XX` and `Last reply: <model>` plus `(fallback at HH:MM)` when the fallback fired today.
- Tests: usage recorded for chat, triage, media and memory calls; missing usage → zeros; cap blocks a group turn and triage but not the owner DM; one notice per day; resets on the next local day; footer content.
- Commit: `feat(usage): record model usage, daily spend cap, show the model in /status`.

### Task 3 (G5): backups

**Files:** `dom/backup.py` (new), `dom/cli.py`, tests.

- `dom backup <home> [--keep 7] [--to DIR]`: default DIR is `<home>/../backups`.
  - `state.db` is copied with `sqlite3.Connection.backup` into a temp file.
  - One archive `dom-YYYYMMDD-HHMMSS.tar.gz` (mode 0600) holds that DB copy plus the home's files, excluding `state.db*`, `.claim` and any `*.bak*`. `.env` is included (the archive is the restore unit; it is owner-only).
  - Keeps the newest `--keep` archives, deletes older ones matching the same name pattern only.
  - Prints the archive path and size. Exit code 1 on failure.
- `dom restore <archive> <home>`: refuses a non-empty home; unpacks safely (reject absolute paths, `..`, links).
- Tests: archive contents and exclusions; DB copy readable with the right row count while a writer connection is open; rotation keeps N; restore round-trip; restore refuses unsafe members and non-empty homes.
- Commit: `feat(backup): dom backup and dom restore`.

### Task 4 (G10): urgent owner messages wake Dom

**Files:** `dom/triage.py`, `dom/dispatch.py`, tests.

- While the **owner DM** is offline or asleep, each debounce runs one Jev call with one question, `urgency` (score): criteria `["casual chat, can wait", "would like an answer soon", "needs Dom now: a task, a deadline, a problem", "emergency"]`.
  - Offline and score ≥ 1.5 → come online and answer.
  - Asleep (sleep hours) and score ≥ 2.5 → wake for 15 minutes and answer.
  - Jev unavailable or refused → no wake from this rule.
- Applies only to `owner_dm`. Thresholds are constants.
- Tests: offline casual → no wake; offline task → wake and one turn; asleep task → no wake; asleep emergency → wake; Jev down → no wake, count rule still works; never runs for a friend DM.
- Commit: `feat(dispatch): urgent owner messages wake Dom`.
