# v0.8.4: Dom knows what happened, and a dashboard that's easy to read

North star (owner, 2026-11-22): the ultimate personality-driven agent on a local stack, with the cloud as fallback.
v0.8.3 gave Dom a voice and a face. v0.8.4 makes him aware of his own life:
- what changed in an update;
- what failed;
- what he actually sent;
- what happened more than a month ago.

It also rebuilds the dashboard around one list pattern that reads well on a phone, and adds the roadmap's goals, noticings, library and source-tagged memory.

Baseline:
- the core design spec;
- the v0.8.1 to v0.8.3 plans;
- the roadmap `docs/superpowers/plans/2026-11-23-roadmap-v0.8.x.md`;
- the owner decisions recorded here and in earlier plans.

## Workstreams

### W1 Dom knows what happened (E73, E79, E83, E84)
- After a successful `/update`, the new release's changelog section goes into the owner DM's context once, as an event Dom reads on his next turn. Today he only gets a 250-character "updated" note.
- Errors reach Dom, as one history note in the chat it happened in. This covers:
  - held, refused or failed photos, voice notes and videos (today they are dropped silently, so he thinks they went out and blames Telegram);
  - guard holds;
  - Telegram send failures;
  - sticker and GIF failures, with fallback text;
  - failed desktop tasks, reminders and plugin runs.
- Media Dom sends gets a vision description stored next to its prompt.
- Native media in (E73): the newest turn's images and audio go to models whose listed input types accept them; descriptions stay for older messages and as the fallback.
- Rescue: an owner command `/fresh` and a dashboard button start a chat's window from now. Earlier messages are hidden from the prompt, never deleted.

### W2 Memory (E75, R13)
Research done (owner, 2026-11-25): `docs/superpowers/notes/v0.8.4-memory-research.md` compares Letta, mem0, Zep, LangMem, ChatGPT, Claude, Generative Agents and A-MEM against Dom. Built in this order:
1. **Journal archive (E75).** `append_journal` moves entries past the last 30 into `memory/journal/YYYY-MM.md` (and `private/journal/`) instead of dropping them. Global search covers the archive. The private archive is owner-DM only.
2. **Dated facts, superseded rather than deleted.** Note lines carry `(as of YYYY-MM)` or `(until DATE)`. A replaced or removed line goes to a sibling `.former` file, so nothing silently disappears. Code, not the model, expires `until` lines.
3. **Source tags (R13).**
   - Each line in people and chat notes carries the chat it came from, or `any`.
   - The prompt builder filters lines in code and strips the tags.
   - Untagged old lines count as `any`, so no migration is needed.
   - MEMORY.md refuses chat-tagged lines.
   - A leak eval comes with it.
4. **Rolling summaries, no month-end cliff** (owner, 2026-11-25: a month boundary would lose context).
   - Entries are archived as they pass 30 days, one at a time, not at month close.
   - Each archived week gets a weekly summary, and months roll up from their weeks.
   - A "recent life" block (the last 4 weekly lines and the last 6 monthly lines) sits after the window, not in the shared system prompt. It is refreshed at most weekly, so the cache cost stays small.
   - Coverage is always continuous: detail for the last 30 days, then summaries.
   - Years roll up from their months.
   - Older periods fade in resolution, not accuracy (owner asked about a half-life): a week gets a few lines, a month a short paragraph, a year a short page. The raw archive is never changed or deleted, so Dom can always look a detail up. Summaries are never made deliberately vague or wrong.
5. **Recency in search.** History search re-ranks its top hits with a soft recency weighting (a half-life of about 60 days). Pinned lines (D18) are exempt.
6. **Light knowledge graph (D19).**
   - Entities: people, chats, places, projects and goals, each with a file.
   - The memory pass that already runs after turns writes each fact's entities, source chat and dates. No extra model call.
   - Code rebuilds an SQLite index from the files: entity, fact, source, dates, links.
   - The index answers "everything about this person, across the chats this chat may see" and "who knows about X". Global search and Dom's search tool use it, and the source tags filter it.
7. **Meaning-based search (D19).**
   - Embeddings come from the home lab's `qwen3-vl-embedding-2b` (2048 dimensions; measured from the Pi on 2026-11-25 at about 0.45–0.65 s for one text and 3.6 s for 16).
   - They are computed in the background as messages and notes change, never on the reply path. Vectors live in SQLite (sqlite-vec), shrunk if the model allows it.
   - Search blends keyword and meaning matches.
   - A query's own embedding runs only when Dom or the owner searches, alongside other work, never before a reply.
   - Fallbacks like every other model role. Vectors from different models (or a different quant) can't be compared, so each vector records the model that made it and a fixed probe text detects drift. A backup embedding model keeps its own index. When no embedding model is reachable, search falls back to keywords and indexing waits.
   - Reindex on demand (owner, 2026-11-25), and automatically when the embedding model changes. The new index builds alongside the old one, and search switches over only once it is complete, so switching models never leaves search empty.
   - Keyword search stays the fast default. Meaning search is a toggle in the dashboard's search and a mode on Dom's search tool.
   - The dashboard shows indexing progress: items done and left, the model in use, and "paused" when the home lab can't be reached.
8. **Core memories** (owner, 2026-11-25: if older periods fade, some things must not).
   - A core memory is a pinned line (D18): it never fades, is never summarised away, and the memory pass never rewrites it.
   - It lives wherever it belongs: MEMORY.md for Dom's own life, a person's notes for a friend. The source tags still apply.
   - The owner pins lines on the Memory page. Dom can propose a pin on an approval card in the owner DM, like his note edits.
   - The Memory page lists all core memories in one view. Their number is capped, so the prompt stays small.
- **Memory page:**
  - preview by default, Edit on demand;
  - the journal preview keeps line breaks;
  - consistent file labels (people show names, not IDs);
  - Import as a button next to Export;
  - the archive and `.former` files are visible and read-only.
- **Not copied:**
  - a graph database server, or a model call per message to extract facts;
  - memory edits before the reply goes out;
  - opaque summaries the owner can't read;
  - decay that deletes;
  - privacy kept only by prompt wording.
