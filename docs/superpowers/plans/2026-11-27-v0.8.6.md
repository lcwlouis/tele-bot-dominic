# v0.8.6: Dom's own calendars, booking, a shared workspace, more Google, and a desk for everyone

North star (owner, 2026-11-22): the ultimate personality-driven agent on a local stack, with the cloud as fallback.

v0.8.5 gave Dom hands, a world and a window. v0.8.6 makes those hands useful day to day:
- his own calendars, and bookings within the windows the owner okays;
- one workspace that he and his desktop share;
- Drive, Docs, Sheets and Contacts;
- a separate desktop for requests from groups and friends;
- the news overnight;
- a pilot of a subscription agent through ACP.

## Workstreams

### W1 Dom's own calendars (E109)
- **Scope:** add `calendar.app.created`. Dom's calendar tool gains `create_calendar`, which asks with an approval card the first time for each new calendar.
- **Writes:** add, move and delete go only to calendars Dom created. Code checks the target calendar id against the list he made; Google enforces it too.
- **Reads:** reads stay on the owner's chosen calendars.
- **Nudges:** each event on Dom's calendars can carry a nudge time. Dom reminds the owner before it, through the existing reminder system, in the owner DM only.
- **Dashboard:** Settings → Services → Google lists Dom's calendars and the read and write switches.

### W2 Booking (E110, D23)
- **Where:** friends' DMs and groups (D23).
- **Windows:** the owner sets them in the owner DM ("weekday evenings 7 to 10, Saturday afternoons") or on the dashboard, and they are stored as structured windows.
- **Flow:**
  - a friend asks to meet;
  - Dom offers up to three slots that are inside a window and free on every calendar he reads;
  - the friend picks one;
  - the owner gets a card with the friend, the time and the context, and approves or rejects;
  - only then does Dom confirm to the friend and add the event to his booking calendar.
- **What leaves:** only the times. Nothing else about the owner's calendar leaves the owner DM, and code filters it.

### W3 The shared workspace and files (E112, D22)
- **Workspace:** `<home>/workspace` is mounted into the desktop sandbox at `/workspace`. Downloads and Dom's own files land there, so the inbox and outbox become a view of it, not a copy.
- **File tools:** owner-DM `files` tools (list, read, write and move within the workspace) with size caps.
- **Dashboard:** a Files page browses the workspace and Dom's readable home files (memory, media, briefs, skills). Its upload and download stay behind the dashboard's auth.
- **Permissions:** the existing download and upload permissions still apply when a file leaves the sandbox through the browser.
- **Sharing toggle (D22):** "Let groups and friends read the shared folder", off by default. With it on, they can read `workspace/shared/` only, and never write.

### W4 More Google: Drive, Docs, Sheets and Contacts (E113, D21)
- **Switches:** each has its own switch and scopes, following W4's pattern (approval cards for writes, owner DM only, untrusted fencing).
- **Drive:** search and read the files Dom may see; create in his own folder.
- **Docs and Sheets:** read; create and append in his own files; every edit through a card.
- **Contacts:** read only, to find who a friend is and their email for booking or drafts.
- **Sharing by link (D21):** when the owner sends a Drive or Docs link, Dom answers with a dashboard link that opens Google's file picker on that file. One click grants Dom that file.

### W5 A separate desktop for groups and friends (E111)
- **Requests:** a group or friend asks, Dom proposes a desktop task, and the owner gets a card (Reject or Allow once).
- **Where it runs:** on a separate desktop container with no saved logins and none of the owner's sessions, on another configured host if there is one; otherwise on the Pi, one at a time, with the owner's logins locked out.
- **Limits:** a step and spend limit per group. Only the final answer goes back to the chat.
- **Before building:** measure the memory of one more sandbox on each host.

### W6 Overnight news (E108)
- **Collecting:** part of the nightly background work. A few headlines and nearby events for the `[world]` place, found with the search route, kept as `memory/NEWS.md` with dates and sources and replaced each night.
- **Prompt:** the "world now" block adds one or two lines from it.
- **Spend:** it obeys the spend caps as background work, and it is off when search isn't set up.

### W7 ACP pilot (E114, D20)
- **Provider:** an `acp` provider kind, with Codex (`codex-acp`), Claude (`claude-agent-acp`) and Antigravity (`agy acp`) as separate entries, each with its own switch, off by default and warned as not ZDR. Owner DM only, as a drafting or escalation role. They run on the Pi where the agent's binary supports it, otherwise on a Mac host.
- **Tools off:** each agent's built-in tools are switched off where the agent allows it, and every permission request is refused.
- **Measure:** latency, quality against the current chat model, and failure modes. The Trace view shows it.
- **Decide:** keep it, or drop it before the gate.
